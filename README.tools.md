## Commands, cheats & input

- **`run_command`** — Send a raw console command to a running, bridge-patched Zandronum instance and return its captured output. Cheats and queued commands print their result a tic later, outside the reply: stepTics then runs the sim that many tics and returns the log lines printed meanwhile (logPattern filters them), leaving the game paused like step.
- **`list_actor_classes`** — Run `dumpactors` and return the registered DECORATE/actor classes as structured data.
- **`summon`** — Spawn an actor of the given class at the player's position (use summon_at for exact map coordinates).
- **`summon_at`** — Run `mcp_spawnat`: spawn an actor at exact map x/y (z defaults to the floor, angle in degrees, 0 east) and report it in the same call, even while paused (it thinks once the sim runs). The reply's class is the actual spawned class after any mod replacement (requested= shows the asked-for name when it differs); use it and the returned tid for follow-ups with find_actors/actor_state. tid defaults to a fresh unique TID; tid 0 means none. kind friend/foe matches summonfriend/summonfoe. The spawn is refused, reporting why, for an unknown class or a spot blocked by an actor, a line or the floor/ceiling fit; force skips that check. An x or y outside -32767..32767, or a z below -32767 or above 32767 minus the actor's height, is refused too, force or not, since fixed point would wrap it. A point in the void is only caught by the floor/ceiling check here, so with findSpot a requested point already behind a one-sided wall can resolve to a spot on that same far side. With findSpot (a radius in map units), a blocked spot is searched outward instead: the actor goes to the nearest spot within that radius where it fits with no wall between (not a walkability check) and the reply reports moved=, its distance from the requested point; if none is free the spawn is refused with the requested spot's own reason. Lights and missiles are never moved. findSpot can't be combined with force. Every spot tested, the requested one included, is a real collision check: a missile damages what it overlaps before it is refused, an overlapped TOUCHY actor dies and a BUMPSPECIAL actor's special can fire. health, special + args (up to 5, zero-padded), ambush and dormant are set at spawn time. Missile classes spawn inert.
- **`set_actor_prop`** — Run `mcp_setprop`: read or write one property on any live actor, the player's body included. Target: tid (omitted or 0 = the console player's body) and index (the nth actor sharing the tid, as find_actors' index=; needs a tid). Props: speed, gravity, friction, meleerange, maxstepheight, maxdropoffheight, damagefactor, damagemultiply, alpha, scalex, scaley, scale, mass, score, accuracy, stamina, reactiontime, friendlyseeblocks, damage, health, height, radius, renderstyle, friendly, dormant, nametag, species, damagetype, or flag:NAME for any DECORATE/ZScript flag name (value true/false; a flag-group prefix such as ACTOR.SHOOTABLE or INVENTORY.QUIET is accepted, an actor class name is not). Numbers are map units/plain values, not ACS fixed point; alpha clamps to 0..1, scale sets both axes, renderstyle takes a DECORATE style name, nametag may hold spaces. Omit value to read the prop instead (old= only). A write reports old= and new= (read back, so a clamp shows), plus the actor's class/tid/hp/position/flags/name; damage reads func/expr for computed damage. health <= 0 kills the actor as a world kill (died=1, removed=1 if it was destroyed); a dead actor's health is refused. height/radius are refused, reporting what blocks, when the actor wouldn't fit; force skips that test. friendly also updates the monster count; dormant reports noop=1 when the dormant bit didn't change (only a live monster's flips; lights and the like toggle without it). The write is direct, so it works while paused, but the actor only acts on it once the sim runs. Refused outside a level, on a client instance (set it on the server) and on a spectator. On a server pass a tid (tid 0 isn't your body there), and only replicated props and flags can be written (others report not replicated); friction, damagemultiply and friendlyseeblocks are unsupported on this engine, and a player pawn's height can't be set (the engine resets it every tic).
- **`place_actor`** — Run `mcp_place`: move, turn and/or launch any live actor in one call and report it after (fromx/fromy/fromz: where it was). Target: tid and index, as set_actor_prop's. x/y/z in map units: a missing x or y keeps the current one; without z, a given x or y puts the actor on the floor there, else z stays. The move is Thing_Move's fit-tested teleport, judged as summon_at judges a spawn, and never telefrags: where the actor wouldn't fit it is refused, reporting what blocks (an actor, a line or the floor/ceiling fit), and then nothing is applied, angle and velocity included. force skips that test; fog spawns teleport fog at both spots. The test is a real collision check, as summon_at's: an overlapped TOUCHY actor dies, a BUMPSPECIAL actor's special can fire and a missile damages what it overlaps. angle and pitch in degrees (0 east, 90 north; pitch negative looks up). vx/vy/vz in map units per tic set the velocity (a missing axis keeps its own), or add to it with addVelocity. Applied in that order (position, facing, velocity), so a move-and-launch isn't stopped. The write is direct, so it works while paused, but the actor only acts on it once the sim runs. Refused outside a level, on a client instance (act on the server) and on a spectator. On a server pass a tid (tid 0 isn't your body there). A z above 32767 minus the actor's height is refused, force or not, since fixed point would wrap its top. A point in the void is only caught by the floor/ceiling fit here. On a server, a client's own body takes back its angle and pitch from that client's next move until the client has the new ones.
- **`remove_actor`** — Run `mcp_remove`: remove the actor with this tid (index: the nth sharing it) or, with all, every actor with it, as Thing_Remove does: no death, and it leaves the kill/item totals. A live player's body is never removed; it is reported as skipped. The reply lists each removed actor as it was, plus the count. Refused outside a level, on a client instance (act on the server) and on a spectator. On a server pass a tid (tid 0 isn't your body there). In a game mode that resets the map, a map-placed actor is hidden instead (hidden=1) and keeps its tid, but every later lookup (these tools, find_actors, actor_state) skips it, as ACS does.
- **`damage_actor`** — Run `mcp_damage`: damage any live actor through the engine's own damage path, as Thing_Damage does: per-type damage factors, pain and death states apply (damageType Extreme forces the extreme death). Target: tid and index, as set_actor_prop's. amount 1..1000000; 1000000 is telefrag damage and gets through god mode and invulnerability. sourceTid (0 = the console player's body) names who dealt it: the target turns on it (target= in find_actors) and, in a netgame, a player source gets the kill credit; single player credits every counted kill to player 0 whatever the source. The reply reports hp before and after (oldhp=, dealt=), nodamage=1 when nothing was lost (not shootable, invulnerable, god mode or a damage factor of 0), died=1 and removed=1. A dead target is refused; heal with set_actor_prop health. The write is direct, so it works while paused; the actor reacts once the sim runs. Refused outside a level, on a client instance (act on the server) and on a spectator. On a server pass a tid (tid 0 isn't your body there).
- **`set_cheat`** — Idempotently turn a player cheat on or off. Reads the cheat bit from the engine-state snapshot and only runs the stock toggle CCMD (god, notarget, ...) when it differs, then waits for the bit to flip, so a blind toggle can never switch it the wrong way. Uses the engine's normal net path. Needs a bridge with the status cap and a cheats= field.
- **`give`** — Give an inventory item. Without a tid, the stock `give` command to the player (cheat names such as all, weapons and health work). With a tid (0 = the console player's body; index as set_actor_prop's), run `mcp_inv` on any live actor instead, as ACS GiveInventory does (class names only), and report held=, the class the amount is kept under (armor: the player's armor class; an ammo pickup: its parent ammo, e.g. ClipBox: Clip; a Health item: health; anything else: itself), with before= and after=. amount (default 1) is ACS's: it sets the item's amount, unclamped, so a Health item heals that much (a Medikit with the default 1 heals 1), an ammo pickup gives that many rounds (times the skill's ammo factor), not its pickup size (a ClipBox with the default 1 gives 1 Clip), and an armor pickup's armor is multiplied by it. With a tid, a bare Armor gives nothing, as in ACS (it is a BasicArmorPickup worth 0), so name a real armor class such as GreenArmor or BlueArmor. An item that turns into something else on pickup (a powerup giver, custom inventory) can read 0 -> 0. ok=0 when the pickup was refused (e.g. health already at max). A given weapon isn't raised. The write is direct, so it works while paused. Refused outside a level, on a client instance (act on the server) and on a spectator. On a server pass a tid (tid 0 isn't your body there). On a server only a player's inventory reaches the clients, so with a tid any other target is refused (not replicated).
- **`take`** — Remove an inventory item. Without a tid, the stock `take` command on the player. With a tid (0 = the console player's body; index as set_actor_prop's), run `mcp_inv` on any live actor instead, as ACS TakeInventory does (class names only), and report held=, the item class itself, the only class looked up, with before= and after=. So taking an ammo or armor pickup or a Health item (ClipBox, GreenArmor, Medikit) takes nothing: name what is held (Clip, Armor). amount (default 1) is taken from the item itself; ammo and armor stay in the inventory at 0. The write is direct, so it works while paused. Refused outside a level, on a client instance (act on the server) and on a spectator. On a server pass a tid (tid 0 isn't your body there). On a server only a player's inventory reaches the clients, so with a tid any other target is refused (not replicated).
- **`load_map`** — Load a map by its lump name (e.g. MAP01, E1M1). Cheats such as god and notarget reset with the map: set them again with set_cheat.
- **`list_running_scripts`** — Run `scriptstat` and return the currently running ACS scripts and their states.
- **`run_script`** — Run an ACS script by number or name, with up to 4 integer arguments. `name` is an alias for a named `script`; a string is always a name, even one made of digits. The script runs inside this call until its first delay, so the reply carries its result value (what SetResultValue set; the engine default is 1 when it never did) and the Log() lines it printed (Print() is a HUD message: use read_hud). A script that paused (at a delay or a wait) reports the value so far with finished=false. One that is already running is not started again (started=false) unless always is set; a suspended copy (ACS_Suspend) resumes instead, with its own args, and reports started=true. The script comes from the first loaded module that has it (module in the reply, numbered as list_modules does), so a run_acs snippet loaded again under the same script name still runs the earlier copy: give the script a new name each time. On a netgame, or a bridge without the runscript cap, the script is queued with puke/pukename instead: it runs a tic later and no result or output comes back. stepTics then runs the sim that many tics and returns the log lines printed meanwhile (what the script logs after its delays; logPattern filters them), leaving the game paused like step.
- **`run_acs`** — Compile full ACS source host-side (bcc by default: zt-bcc or bcc on PATH, with zt-bcc's lib/ found next to or one folder above the binary; or acc on PATH; ZANDRONUM_BCC/ZANDRONUM_ACC override the executables) and load it into the running level as a temporary module, then optionally run one of its scripts by number or name with up to 4 args (a string script is always a name, even one made of digits; `name` is an alias for a named `script`). The script runs inside this call until its first delay, so its Log() output comes back in the reply (Print() is a HUD message: use read_hud); stepTics then runs the sim that many tics and returns the log lines printed meanwhile (logPattern filters them). A snippet that isn't a #library is compiled as one, so its strings resolve. It may #import a library the level already loaded (pass includeDirs for its source) and then shares that library's live functions and map vars; importing a library that isn't loaded is refused before anything is sent. ZANDRONUM_RUNACS_PROFILES lists per-project profile files: a profile applies when the snippet #imports one of its libraries, adding its include dirs and its defines (which #import doesn't carry) ahead of the snippet, and the reply names it (profile: <file>); a profile with rawDefines makes the snippet's own #defines case-sensitive. open runs its OPEN scripts. Compile errors come back without touching the engine. Offline only (no server/client). Zandronum can't unload a module: one the engine rejects stays loaded, inert, and every snippet stays until the map changes. While any is loaded save_game refuses: a save would fail to load (in-game saves and leaving a hub level carry the same hazard, which this tool can't intercept).
- **`screenshot`** — Take a screenshot of the game and return it as an image so it can be viewed.
- **`screenshot_file`** — Take a screenshot and leave it on disk, returning only its absolute path (no image content). For measuring pixels with a script instead of viewing the frame. A reused `name` overwrites that file.
- **`menu_key`** — Send a single menu navigation key (GUI key event) to the active menu.
- **`menu_nav`** — Send a sequence of menu keys (e.g. ["down","down","enter"]) with a small delay between each.
- **`menu_text`** — Type a string into the active menu text-entry field (e.g. the player name box after pressing enter on it), one character at a time.
- **`mouse_move`** — Move the pointer to a screen position, in pixels from the top-left of the game window. Drives hover-only UI -- tooltips, hot states -- which nothing else here can reach.
- **`mouse_click`** — Press and release the left button at a position. Give toX/toY to DRAG: press at the first point, move through it, release at the second. `double` sends a double-click.
- **`mouse_wheel`** — Wheel notches at the current pointer position. Positive scrolls up, negative down.

## Time control

- **`set_pause`** — Set the engine's master pause flag directly. Use this to resume a backgrounded instance that auto-paused on focus loss, so the simulation keeps advancing while the MCP drives it. all applies it to every instance this session has bound instead of one, with a line per instance (e.g. to resume a whole netgame). Pausing a netgame server or client adds what pause means for that role.
- **`step`** — Resume the game, let it run for the given number of tics (35 tics = 1 second), then pause again. Lets you advance the simulation a deterministic-ish amount to observe time-based effects (charging, projectiles, animations) without keeping the window focused. Returns the engine log lines printed meanwhile (up to 50, with a read_log resume point for the rest; logPattern filters them); a quiet step adds nothing. On a netgame the reply adds what pause means for the instance's role, and a client is left running instead of paused again.
- **`ensure_live`** — Prove the simulation actually advances: list what could block it (menu, console, chat, automap, not in a level, dead/spectating player, demo, a pending map/save/demo load), then run it ~5 tics and check the map tic counter moved. A pending load is waited out first (up to ~5 s). The pause state is left as found, since `paused` is the normal driving state and `step` runs through it. With fix, first closes the menu (`closemenu`) and hides the console, chat and automap (`mcp_unblock`). Returns live plus the blockers found, fixed and remaining.
- **`step_until`** — Advance the sim in chunks of chunkTics until a condition holds or maxTics run out, then leave it paused like `step`. The condition compares a map var, map array element, ACS world/global var, player field (x, y, z, angle, floorHeight, sector, light, health, armor) or the count of actors find_actors' class/tid/radius/flags filter matches (a corpse counts unless flags rules it out, e.g. {alive: true}) against a number, or a player field against another field (e.g. z == floorHeight); or, kind log, holds once a line matching pattern (a case-insensitive regex) is printed after the call starts (value is the matching-line count). Reports the map tics that actually elapsed. Fails fast with the blocker list if the map tic counter stops for 5 tics, and fails if it goes back (a map change). On a netgame the reply adds what pause means for the instance's role, and a client is left running instead of paused between chunks.
- **`watch_actors`** — Sample the actors of a class (subclasses included) and/or TID over the next `tics` map tics (35 = 1 second) in one call: snapshot with `findactors`, step everyTics paused, repeat, then leave the game paused like `step` (a netgame client is never re-paused, and the reply adds the role's note). For short-lived projectiles and effects, or a monster's path, instead of find_actors/step polling. Returns one table (columns maptime plus fields, one row per actor per sample, a missing key null) and a per-class summary (first/last maptime seen, most at once, samples present). Rows are per-sample snapshots: there is no identity across samples for actors without a unique TID, so a class watch can't tell which row is which actor. An actor living under everyTics can fall between snapshots; use everyTics 1 for those. limit caps each snapshot (cut ones are counted), maxRows the table (past it the summary stays exact and dropped rows are counted). Reports reason done, gone (untilGone: matches were seen and the latest snapshot has none; an empty start waits for a spawn), level_change (the map tic counter went back: the map changed or restarted, and the table ends before it) or stalled (the counter stopped for 5 tics; the only error).
- **`move_to`** — Walk the player to a map point ({x, y}), an actor ({tid}: the nearest with that TID, followed if it moves; {class}: the nearest of that class when its leg starts, walked to where it stood then) or through a route of up to 32 of them, with the steering loop inside the server: holds +forward, re-aims whenever the heading drifts and times the release from the player's measured speed, thrust and friction, without pausing between chunks. Straight legs only: walls are not avoided, so route around them with waypoints (pre-check a leg with trace_move). Intermediate waypoints are passed through; the last counts once the player is within radius (plus an actor target's own radius) and has stopped. Reports reason arrived, stuck (no progress in stuckTics: the closest approach gained under 8 units and the player didn't speed up toward the target), timeout (maxTics, whole route), died, player_gone (no player, or a level change), target_gone, or stalled (sim not advancing; the only error), plus the map tics elapsed, the final position and speed (above 0 after timeout/died/target_gone, the player is still sliding). +forward is always released and the pause state is left as found. Unverified on a netgame client. For setup moves where movement isn't under test, use run_command `warp x y` (cheats on) plus set_view instead.
- **`input_timeline`** — Run a list of input segments in one call, each holding buttons, movement and a heading for N tics, injected into the player's input by the engine every tic for exactly the tics asked (35 tics = 1 second, up to 64 segments and 60 s). A tap is a 1-tic segment, a hold is one long segment, a release is a segment without the button. Returns one line per segment with the map tics it ran in, where the player went, the heading and health after it, and the log lines printed during it; trail adds a per-tic row (position, angle, pitch, momentum, health, buttons). While it runs, the real keyboard and console-held buttons (+attack, +forward) are ignored; they come back after. Button rules: use needs a released tic between presses; attack refires while held unless the weapon has NOAUTOFIRE; jump needs the ground; a freshly spawned player needs one released tic before its first attack or use counts. Switch weapons with run_command first: a weapon change is not an input field. Offline only (refused on a server or client), and refused with a menu, console, chat or automap open or a dead player (ensure_live with fix clears those). Death mid-run doesn't stop it (health shows it). Reports reason done, level_change (the map ended or changed; later segments didn't run), stopped, or stalled (tics stopped running; the only error). The pause state is left as found (a run that ends at an intermission leaves it unpaused). A demo recorded meanwhile holds the real input, not the injected one.

## ACS world/global variable read/write

## Static ACS source index

- **`acs_index`** — Parse a directory of .acs source files and return symbol counts (scripts, functions, numeric defines). Reads files directly; no game needed.
- **`find_acs_symbol`** — Resolve a script number or a script/function name to its symbol(s) — name, number, file:line. Turns a profiler 'script 1017' into a source location.
- **`behavior_names`** — Read function and named-script names from a mod's compiled ACS (BEHAVIOR/library lumps) in a WAD or PK3 — for source-less mods. Numbered scripts have no names in bytecode (use find_acs_symbol with source for those).
- **`list_map_exports`** — List each ACS module's exported map variables and arrays (MEXP/ARAY chunks) from a WAD, PK3, directory or compiled .o, with slot index and array size. These are the names get_map_var/get_map_array find by name; anything else needs their sourceFile. `lump` narrows to modules whose name or basename matches (e.g. `mymod` for `acs/mymod.o`); a map's BEHAVIOR also matches `BEHAVIOR` or its map marker.

## Savegames & demos

- **`list_saves`** — List .zds savegames in the save directory with metadata (title, map, engine, game wad, creation time) read from each save's PNG text chunks. No running game needed.
- **`save_game`** — Run `save` to write a savegame (single-player / cooperative only). NOTE: saving heavily-scripted mods can crash the engine — All-out-War crashes on save; vanilla and simple maps save fine.
- **`load_game`** — Run `load` to restore a savegame by name.
- **`play_demo`** — Run `playdemo` to play back a recorded .lmp demo. (Recording is via the -record launch arg, not a console command.)

## Live player / target state

- **`player_state`** — Run `currentpos` and return the player's position, angle, floor height, sector, light level, and (on a status-capable bridge) health, armor, and whether the player is alive, dead, or spectating.
- **`actor_state`** — Run `dumpactor` and return an actor's live state: class, health, position, angle, pitch, current DECORATE state (sprite/frame/tics, e.g. TNT1 A 0, plus id Owner.index and label e.g. See+2), inventory, and (for players) ready weapon + morph status. For a player, `player` also holds the tic's input: `input` raw (GetPlayerInput INPUT_*) and `modInput` after mods (MODINPUT_*), buttons decoded to names; use `input.oldButtons` for press edges, since between tics `modInput.oldButtons` already equals `modInput.buttons`. Plus `weaponFlags` (weaponready, ...), `refire`, `pendingWeapon` (null: no change pending; "none": switching to no weapon) and every active psprite layer (weapon, flash, or its GZDoom layer number) with sprite/frame/tics/x/y and the state's id/label (e.g. Fire+1). Read right after `step` for exact per-tic values; `player` is null for a non-player. Defaults to the player; pass a TID for any actor, plus index for the nth actor sharing it.
- **`read_hud`** — Run `dumphud` and return what the engine painted last frame: HUD text strings (with screen x/y), images (by texture name + position), and active ACS HUD messages (full composed text, layer, position, remaining tics). Captures menus too. Filtered server-side: pattern is a case-insensitive regex on a string's or message's text or an image's name; region keeps text and images whose x/y (the same values the results report) fall inside it, and never filters messages, which use another coordinate space; maxItems (default 100) caps each kind, keeping the first in draw order, and omitted counts what the cap left out.
- **`actors_near`** — Run `actorsnear` and return actors within a radius (map units, default 512) of the player: class, health, position, and current sprite.
- **`inspect_target`** — Run `linetarget` and return the actor the player is aiming at (class, health, spawn health).
- **`set_view`** — Point the player's view: an absolute angle (degrees, Doom convention: 0 east, 90 north) with optional pitch (degrees, negative looks up), or face an actor by tid (first actor with it) or class (nearest map actor of that class, aiming at its mid-height). Give exactly one of angle, tid, class.
- **`list_players`** — Run `dumpplayers` and return every in-game player: slot, bot, host (offline only: a server owns no player slot), spectator/dead-spectator, player state, health, armor, ready weapon, x/y/z, angle, pitch, TID, cheat bits, frags, deaths, kills/items/secrets, points, wins, team, ping and name. Bots join at slot 1+.
- **`add_bot`** — Add count bots (`addbot`), step the sim until each has joined, and return each one's slot, name and TID. A join can take a tic or two; the sim runs in chunks of chunkTics, up to maxTics. A bot that joins as a spectator (a join queue) is reported as one. A bot whose TID is 0 is waited on up to tidTics more for a script to assign one (tidTics 0 skips that); it stays 0 when nothing does. Reports the map tics elapsed (across a map change mid-wait, the old map's plus the new one's). A bot that joined and then a map change removed mid-wait is listed as lost (reason level_change); the call fails when none is left. Fails fast when the map tic counter stops for 5 tics. The pause state is left as found. Fails with what addbot printed when no bot joins (an unknown name, no free slot, not in a level). For a team, use run_command `addbot <name> <team>`.
- **`find_actors`** — Run `findactors` and list map actors (owned inventory excluded), optionally filtered by class (includes subclasses), TID and radius around the player, sorted by distance. Each has class, tid, hp/spawnhp, x/y/z, angle, pitch, dist, sprite/frame, flags (monster, friendly, corpse, dormant, shootable, solid, invulnerable, ambush) and target. detail adds master/tracer, special + args, vel, radius/height, floorz and player index. flags keeps only actors matching every given key (true = must have, false = must not), each a flag name above or alive (derived: hp > 0 and not a corpse; decorations count, so pair it with monster); use {monster: true} for all monsters instead of guessing a base class, and with flags, limit (default 200) applies after filtering. With a tid filter each result also has index, the one to pass to actor_state(tid, index) for it (the list is in distance order, not index order).

## ACS scripts / functions / profiling

- **`list_scripts`** — Run `dumpscripts` and return every script across loaded modules (module, number, name, type, arg count).
- **`list_functions`** — Run `dumpfunctions` and return named ACS functions across loaded modules.
- **`profile_scripts`** — Run `acsprofile` and return per-script/function execution stats (total instructions, runs, avg/min/max). Rows are the top 10 per section (scripts, functions) by `sort` (default total, all descending); `limit` raises that, and the reply counts every profiled row. A name the engine's 20-character column cuts (a script name over 18 characters, since it prints quoted, or a function name over 20) is resolved from dumpscripts/dumpfunctions when exactly one name fits, else kept as the printed prefix with truncated: true. Stock Zandronum builds (not the MCP fork, which fixes it) never profile `busy` scripts: they are missing from the list, and functions they call show 0 instructions per run.
- **`profile_window`** — Clear ACS profiling, wait N seconds, then return what ran during that window — `what's hot right now` rather than cumulative since map start. Rows are the top 10 per section (scripts, functions) by `sort` (default total, all descending); `limit` raises that, and the reply counts every profiled row. A name the engine's 20-character column cuts (a script name over 18 characters, since it prints quoted, or a function name over 20) is resolved from dumpscripts/dumpfunctions when exactly one name fits, else kept as the printed prefix with truncated: true. Stock Zandronum builds (not the MCP fork, which fixes it) never profile `busy` scripts: they are missing from the list, and functions they call show 0 instructions per run.

## Map-scope ACS variables/arrays

- **`list_modules`** — Run `dumpmodules` and return the loaded ACS modules (id + name). Map vars live only while a map is loaded.
- **`get_map_var`** — Read a map-scope ACS variable by name (searched across loaded modules, exported names only), or with sourceFile any map var by expression.
- **`set_map_var`** — Write a map-scope ACS variable by name (exported names only), or with sourceFile any map var by expression.
- **`get_map_array`** — Read one element of a map-scope ACS array by name (exported names only) and index, or with sourceFile of any map array (name is then an expression, read at name[index]).
- **`set_map_array`** — Write one element of a map-scope ACS array by name (exported names only) and index, or with sourceFile of any map array (name is then an expression, written at name[index]).

## Map probes

- **`point_info`** — Run `mcp_pointinfo`: the live sector at map x/y with its floor and ceiling height (the bare planes, as GetSectorFloorZ/CeilingZ; floor3d/ceiling3d when a solid 3D floor around z differs), floor and ceiling texture (the surfaces around z, as CheckActorFloorTexture sees them), light, special and tag, and inmap (0 in the void; omitted when the map has no GL nodes). With radius and height, or a mover (whose size fills in any not given), also whether an actor that size fits there (at z, else on the floor): ok, or reason actor (blocker), line, ceiling, floor (z below it) or slope. Only the mover is set aside, so without one the player standing there blocks the fit itself (actor blocker=player0). Collision runs on a throwaway probe actor shaped like the mover, which moves like a monster of its size: a player's step-up onto low actors isn't modeled. Player-only blocking lines are honored for a player mover. Probes are refused on a netgame client and during demo playback or recording.
- **`check_sight`** — Run `mcp_checksight`: whether the engine sees a line of sight between two actors or map points, as ACS CheckSight does (from the eye at 3/4 of from's height to any part of to; invisibility ignored). A point ({x, y, z?}) is a 1-unit-high probe at z or the floor, so its eye is 0.75 above that: pass z (e.g. floor + 41 for a player's view) to look from eye height. water: true ignores Boom deep-water boundaries; pastBlocking: true sees past block-everything lines. When not visible, line names the first line a straight trace from eye to target middle hits, a hint that may be missing. A point needs a probe, refused on a netgame client and during demos.
- **`trace_move`** — Run `mcp_tracemove`: whether the mover (default the player, none on a netgame server; its size and step/dropoff limits, radius/height override the size) walks straight from `from` (default its position) to `to`, stepping a probe at most radius-1 units at a time and testing each step as the engine's movement does. Reports ok, or where it stops (x/y/z, dist of total) and why: line, actor (blocker; actors: false ignores actors), step (rise above the step height), ceiling, dropoff (drop, for a walking monster or NODROPOFF), slope or outside. Geometry only: no momentum, line specials (teleporters, crossing triggers), moving sectors or damaging floors. Collision runs on a throwaway probe actor shaped like the mover, which moves like a monster of its size: a player's step-up onto low actors isn't modeled. Player-only blocking lines are honored for a player mover. Probes are refused on a netgame client and during demo playback or recording. Pre-check a move_to leg with it.

## Process management

- **`launch_instance`** — Spawn a bridge-enabled Zandronum process with the given options and attach to it (with wait: false, on its first tool call instead). Requires ZANDRONUM_EXE to be set.
- **`relaunch_instance`** — Quit an instance this session launched and start it again with the same options (iwad, files, map, skill, window, extraArgs, config, wait), e.g. to pick up DECORATE/MAPINFO edits. Any option given here replaces the stored one for this and later relaunches; [] clears files/extraArgs. Refuses for an attached instance.
- **`attach_instance`** — Connect to a bridge-patched Zandronum that is ALREADY running — one you launched by hand, or from a terminal — and bind it to an instance number for the other tools. Only needed for engines this session didn't launch: launch_instance binds automatically. Defaults to this instance's conventional port. Refuses an instance whose launched engine is still running.
- **`join_game`** — Bring netgame clients from spectating into the game: for each, wait until its own status shows it in a level, send the join command, and poll until it no longer spectates (a join lands a tic or two later). Idempotent: an already-joined client is just reported, so re-run it after a server `map`, which sends every client back to spectating. instances defaults to every bound instance launched with the client flag; a server is refused. slot is the player whose name matches the client's `+name` launch arg in its dumpplayers. Reports per client joined, or still spectating / connecting after timeoutSec.
- **`kill_instance`** — Stop a launched instance and detach from it. Asks the engine to quit itself first (a hard kill mid-render can wedge macOS GPU teardown and leave an unkillable process), then force-kills if it doesn't exit. A wait: false instance not attached yet is attached first if its bridge is up; one whose bridge isn't up is force-killed at once.
- **`reset`** — Kill every instance this session launched, and reap engines ORPHANED by earlier sessions (whose launcher is gone) that could otherwise squat bridge ports. Engines belonging to another running editor window are left alone. Pass all:true to also kill those — only do that if you know no other session is using this engine build.
- **`get_startup_errors`** — Read the engine's captured console log and stderr for an instance and surface DECORATE/ACS compile errors and fatal startup errors (the fatal text itself is on stderr). Works even when the bridge never came up (e.g. the engine aborted on a bad script) — exactly when the other tools can't connect. On a live instance the stderr part may hold harmless SDL/audio warnings.
- **`read_log`** — Read an instance's engine console log, which catches prints that never come back in a command reply (e.g. cheat ON/OFF messages, emitted a tic later). Correlation sentinel lines are dropped. `pattern` is a case-insensitive regex filter and `exclude` one that drops what it matches. Without `sinceLine` this returns the last `maxLines` matches; with it, the first `maxLines` matches after that line. Pass the returned `nextLine` as `sinceLine` to read only what was logged since. `count` returns only how many lines match (all of them, ignoring maxLines; with sinceLine, only the new ones). The reply names the log file (`log=`): it is this instance's own (one per bridge port), so Bash can grep it directly.
- **`wait_for_log`** — Poll an instance's engine log (the file read_log reads, so a busy bridge doesn't block it) until `count` lines matching `pattern` (a case-insensitive regex) appear after `sinceLine`, the engine exits, or timeoutSec of wall-clock time passes. For netgames, which can't be stepped: wait on a marker a server or client prints. sinceLine 0 (the default) means since this launch, so a line printed before the call still matches; pass a previous call's nextLine to wait for a new occurrence. Never touches pause, and a paused game logs nothing new (a paused netgame client holds back what the server relays): offline, step (or run_command/run_script with stepTics) with logPattern is the tic-exact way. Reports reason matched, timeout or exited; only an invalid pattern is an error.
- **`read_marks`** — List the playtest marks a human left with the `mcp_mark [note]` console command (bind it once with `bind <key> mcp_mark`), read from the instance's console log: per mark its number n, tic (gametic, runs while paused), maptime, map, player position/angle (none on a netgame server, which has no player of its own), round (from the script the `mcp_mark_round` cvar names; "none" when that script isn't loaded), invasion wave, screenshot name and note. Pass `mark` (n) for that mark plus its screenshot as an image. The console log is rewritten each launch; for an earlier session's marks pass `gamelog`, an absolute path or a gamelog file name in the dir launches write gamelogs to (ZANDRONUM_BRIDGE_GAMELOG's, else the engine's default).
- **`get_crash`** — Return the signal, faulting address, and symbolized backtrace the bridge's crash handler captured the last time the engine crashed (segfault/abort/bus error/etc.). Use this when an instance dies unexpectedly — e.g. run_command reports the bridge closed. Says so if the instance has not crashed, with the tail of the engine's captured stderr when there is one (an in-game fatal error exits without a signal, and its text is only there; on a live instance it may hold harmless SDL/audio warnings). A report left by another engine (different PID) is named but not returned as this instance's crash; one that can't be tied to this engine (its PID is unknown, or the report has no pid line) is returned marked `Unverified:`.
- **`process_stats`** — Read the instance's engine process memory from /proc/<pid>/status (Linux only): vmRssKib (resident now), vmHwmKib (peak resident since start) and vmSizeKib (virtual), all KiB, plus the pid and the kernel's process name (cut to 15 characters). Reads the file directly, never the bridge, so a busy or hung engine still answers. Fails, never reports zeros, when this session knows no engine PID for the instance (not launched or attached here, or killed since), the process has exited, or the file is unreadable or lacks those fields (no /proc, a zombie), or the process name isn't the engine executable's (a server outside the engine's PID namespace sees another process at that PID).

## Scenarios

- **`run_scenario`** — Run up to 64 steps on one instance inside the server and return every result in one reply, instead of a round trip per call: setup bursts, summon waves, map-array sweeps, step-then-check loops. A step is {call, args}, any instance tool by name with its own args (the scenario's instance is used, so args carry none); {expect: condition}, which fails when the condition doesn't hold; or {repeat: [call and expect steps], until?: condition, maxIterations (up to 200)}, which runs its body until the condition holds after a pass and fails if it never does (without until, exactly maxIterations passes). Conditions are step_until's; a log condition counts lines printed since the scenario began. E.g. {repeat: [{call: "step", args: {tics: 5}}], until: {kind: "actors", class: "DoomImp", flags: {alive: true}, op: "==", value: 0}, maxIterations: 40} runs until every imp is dead (without the alive flag a corpse still counts). Every call step's tool and args are checked against that tool's own schema (an unknown arg too) before anything runs, so a typo in a late step drives nothing; launch_instance, relaunch_instance, attach_instance, kill_instance, reset, screenshot, verify_menu (screenshot_file stands in for a frame) and tools without an instance are refused. Without sinceLine, a read_log step reads on from the last read_log (the first from where the scenario began), and a wait_for_log step waits for a line printed since the scenario began, not since launch. A wait_for_log that times out is not a failed step (its reply is no error); follow it with {expect: {kind: "log", ...}} when the run should stop there. onFail stop (default) ends the run at the first failed step (an error reply, an unmet expect or until); continue runs the rest. A thrown error, a client cancel, 256 calls in all, or maxSeconds of wall clock end it either way, and a run that ended at a failure is an error reply. These are checked between calls, so one long call (wait_for_log, step_until, watch_actors, input_timeline) can run past maxSeconds by its own timeout. The reply is structured: ok, failedAt (the first failure), calls, maptimeStart and maptimeEnd (the map tic counter around the run: count elapsed tics by these, since a step's tics are asked for, not measured, and an engine's step can run short; a map loaded mid-run restarts the counter, and a note says so when it ends below where it began), and per step its index, ok, text (cut at 500 chars) and structured result (arrays cut to 20 rows, fewer until it fits 2000 chars, with omitted counts and a hint to call that tool on its own); a repeat keeps its last pass's results and its iteration count. Past 24000 chars of step results, later steps keep only their kind and ok, and a failed one its text's first line, cut at 100 chars.
